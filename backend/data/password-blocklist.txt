# READ THIS BEFORE RELYING ON IT.
#
# This file is NOT what enforces the policy. `tsc -p backend/tsconfig.json` copies
# no non-.ts files, and pm2 runs dist/backend/index.js, so this file DOES NOT
# EXIST in a production build. The guarantee is CORE_BLOCKLIST in
# backend/services/password-blocklist.ts, which is compiled and always present;
# a missing or unreadable file here is logged and ignored, never fatal.
#
# It exists so the list can be widened without editing code, and so a real
# wordlist can be dropped in: SecLists' top-10k, rockyou, or an internal list of
# strings this organisation has seen. If you want that widening to reach
# PRODUCTION, either add an asset-copy step to the `backend:build` script or move
# the entries into CORE_BLOCKLIST — do not assume this file ships.
#
# One entry per line. Blank lines and lines starting with `#` are ignored.
# Entries are normalized on load (lowercased, NFKC, symbols and punctuation
# stripped, a trailing digit run dropped, leet folded), so write them in plain
# human form: `Пароль123!` and `пароль` end up as the same entry.
